# Phase 4: Investigate

Goal: find out by experiment why the antenna misses its band and what would fix it. This review allows {investigations} investigation(s) with up to {experiments} experiments each (a what-if run or a matching experiment). You have {phase4_calls} tool calls.

How to read a result, in this order:
- S11 across the band, as built. Success is the worst S11 in {band} (target {target_db} dB). The deepest dip is only a description.
- The impedance at the band centre. A large reactance says matching can help: inductive means the antenna looks too long for the band, capacitive too short.
- Every dip, not just the deepest. A dip that does not move when the antenna length changes is probably a board mode (the ground plane), not the antenna's own resonance. `compare_results` tells you which dips stayed put.

Do this:
1. `open_investigation` with one clear question and up to three suspects, ranked by likelihood. Cover what could explain it: the antenna length, the matching network, nearby copper or parts, a board mode. Say in one line why each is a suspect.
2. Run the base case first: `run_simulation` with no `whatif_ops`. Everything is compared with it.
3. Test one suspect at a time. What-ifs you may simulate: `adjust_antenna_length` (up to 12 mm either way), `clear_copper_region`, `remove_nearby_part`, `set_material` (permittivity 3.8 to 4.8). They exist only inside the simulation.
4. Matching is an experiment too. `tune_matching` on a trusted run (the base, or any what-if, to try a combination) costs no solver time and counts against your experiments. Pass the suspect it tests.
5. Read each result before choosing the next test. Two tests in a row that change the in-band result by under 0.5 dB and 5 MHz close the suspect. If a result surprises you, test the surprise.
6. Screen runs only compare; the confirm run proves. In `conclude_suspect` and `close_investigation` you may quote a screen number if you say it is a screen result or a comparison with the base. Findings and the summary need confirm numbers.
7. `conclude_suspect` for each suspect: confirmed, ruled_out or inconclusive, after a trusted experiment.
8. Do not stop early. While budget remains the server refuses to close without an improvement until you have run a matching experiment and tested at least two suspects. If anything improved the worst in-band S11 by 1 dB or more, `record_finding`, then close as improved: phase 5 checks it at confirm quality.
9. If the tuning target is met, stop optimising. Then `close_investigation` with the finding code and `advance_phase`.

Do not repeat a request that already has an answer. A failed trust check may be repaired once per scenario by changing `setup`; after that the suspect ends as could not test.
