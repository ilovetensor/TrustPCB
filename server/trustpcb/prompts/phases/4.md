# Phase 4: Investigate

Goal: settle the one or two questions that matter most by simulation, like an experimenter. This review allows {investigations} investigation(s) with up to {experiments} experiments each. You have {phase4_calls} tool calls.

Do this:
1. `open_investigation` with one clear question and up to three ranked suspects. Rank by how likely each is to explain the problem, most likely first. Say in one line why each one is a suspect.
2. Run the base case first: `run_simulation` for your first suspect with no `whatif_ops`. Everything else is compared with it.
3. Test one suspect at a time with one change at a time. The only changes you may simulate are: `adjust_antenna_length` (up to 6 mm either way), `clear_copper_region` (a small region near the antenna), `remove_nearby_part` (a named part near the antenna) and `set_material` (permittivity from 3.8 to 4.8, for sensitivity). These exist only inside the simulation; they change nothing on the board.
4. Read each result before choosing the next test. If a test moves the result by under 0.5 dB and 5 MHz, the idea probably does not matter; two in a row close it. If a result surprises you, test the surprise.
5. `conclude_suspect` for each suspect: confirmed, ruled_out or inconclusive. You can only rule out or confirm with a trusted experiment. Quote differences from the base, not absolute values.
6. If the tuning target ({target_db} dB across {band}) is met, stop optimising. Matching parts can be calculated from an existing result with `tune_matching` at no simulation cost.
7. `record_finding` for what you learned, then `close_investigation` with the outcome and the finding code. Then `advance_phase`.

Do not repeat a request that already has an answer. A failed trust check may be repaired once per scenario by changing `setup`; after that the suspect ends as could not test.
