# Phase 5: Confirm

Goal: make sure a claimed improvement is real. Screen runs only compare; a detailed run proves. You have {phase5_calls} tool calls and {confirm_runs} confirm runs in total.

Do this:
1. `confirm_result` with `which` set to `base`, then `winner`. The winner is a pair: what-if changes plus matching parts. A matching-only winner reuses the base run, so it costs one run. The server then re-tunes the matching at confirm quality, first with the screen's parts locked and then free, and reports both.
2. If the confirm run disagrees with the screen run, believe the confirm run and say so.
3. If the improvement does not hold, say it plainly: "the screen improvement did not hold at confirm quality". The server records it in the finding; do not hide it or soften it.
4. Update the finding with `record_finding` (use `update` with its code). A finding about the antenna quotes confirm numbers only, from confirm evidence with trust ok. Candidate changes are worded as tested in simulation, for the engineer to apply in their own tool.

Then call `advance_phase`.
